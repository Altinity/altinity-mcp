01 / 21
01 / thesis

A database-defined application, not just a SQL chatbot.

Use the host as the interface and agent runtime; give it narrow, meaningful application capabilities.

DATA

Read and write

  • Parameterized views: named, typed read operations.
  • Insert-only command tables: domain-specific write operations.
  • DEFAULT expressions and materialized views: generated fields, projections and derived events.
EXPERTISE

Skills and resources

  • SKILL.md and reference content stored as rows.
  • Guide the agent through business workflows and semantics.
  • Expose contextual documents and citations, not the entire database.
EXPERIENCE

UI and reactions

  • HTML/CSS/JS components from ClickHouse via MCP Apps.
  • MCP Events wake a subscribed agent on important changes.
  • Tasks and Elicitation extend jobs and decisions when the host supports them.
Boundary

No app-specific persistent state or business rules in Go. Generic protocol code, identity infrastructure, delivery workers and browser-side interaction still exist. The host chooses when a tool is called; ClickHouse enforces what is allowed.

05 / build the data model

1. Store domain state and commands.

Example: a single-tenant append-only incident journal. Add tenant-specific identity and policies for a real deployment.

SQL
CREATE DATABASE IF NOT EXISTS app;

CREATE TABLE app.open_incident
(
    request_id UUID,
    title String,
    severity String,
    incident_id UUID DEFAULT generateUUIDv7(),
    opened_at DateTime64(3) DEFAULT now64(3),
    CONSTRAINT valid_severity
        CHECK severity IN ('critical', 'high', 'normal')
)
ENGINE = MergeTree
ORDER BY (opened_at, incident_id)
COMMENT 'Open an incident';
DESIGN

Use commands, not arbitrary SQL

  • A request has a domain meaning; only required columns are exposed to the agent.
  • Database-generated IDs and timestamps are omitted from tool inputs.
  • Add append-only note and resolution command tables; project a current incident view from the journal.
  • Use constraints, roles and controlled views/MVs to enforce the supported invariants.
Production assumption

MergeTree ORDER BY is not a unique constraint. request_id is a correlation key, not an exactly-once guarantee. Validate idempotency and concurrency separately; if strict cross-row transactional invariants are mandatory, use a transactional subsystem rather than promise SQL-only correctness.

06 / read tools

2. Publish typed read operations as views.

Business queries stay in ClickHouse; the connector discovers typed inputs and executes with the caller's credentials.

SQL
CREATE VIEW app.list_incidents
SQL SECURITY INVOKER
AS
SELECT incident_id, title, severity, opened_at
FROM app.open_incident
WHERE severity = {severity:String}
ORDER BY opened_at DESC
LIMIT 100;

-- Example invocation in ClickHouse:
SELECT *
FROM app.list_incidents(severity='critical');
YAML
# Existing Altinity MCP configuration:
server:
  tools:
    - type: read
      name: list_incidents
      view_regexp: '^app\.list_incidents$'
    - type: write
      name: open_incident
      table_regexp: '^app\.open_incident$'
      mode: insert
Expose only the application API

In a plugin deployment configure only intended read/write rules; omit raw execute_query and write_query unless the product is explicitly a SQL workbench. Use least-privilege credentials even when a tool is hidden. The example targets one exact view and table; test tool names and schemas via tools/list.

07 / write tools

3. Return real application outcomes.

ClickHouse 26.11+ gives each insert-backed write tool a programmable response, without a follow-up SELECT.

SQL
ALTER TABLE app.open_incident
MODIFY COMMENT '{
  "title": "Open incident",
  "description": "Create an incident and return its ID.",
  "returning": "SELECT incident_id, opened_at, severity"
}';

-- Generated SQL (illustrative)
INSERT INTO app.open_incident
    (request_id, title, severity)
RETURNING (SELECT incident_id, opened_at, severity)
VALUES ('11111111-1111-4111-8111-111111111111',
        'Ingestion lag', 'critical');
Illustrative result object
{
  "columns": ["incident_id", "opened_at", "severity"],
  "types": ["UUID", "DateTime64(3)", "String"],
  "rows": [
    ["019b0000-0000-7000-8000-000000000001",
     "2026-11-26T11:00:00.000Z", "critical"]
  ],
  "count": 1
}
Do not overstate RETURNING

The response describes inserted blocks after defaults, not necessarily final persisted state or downstream MV output. It stays a write; consume the stream to completion, bound retained response bytes, do not blindly retry ambiguous writes. Verify native driver protocol revision 54495 or use verified HTTP.

08 / skills

4. Store workflow expertise in the database.

Native MCP Skills when available; an explicit compatibility path where it is not.

SQL
CREATE TABLE app.mcp_skill_resources
(
    skill_path String,
    path String,
    mime_type String,
    content String
)
ENGINE = MergeTree
ORDER BY (skill_path, path);

INSERT INTO app.mcp_skill_resources VALUES
('incident-triage', 'SKILL.md', 'text/markdown',
'---
name: incident-triage
description: Investigate and triage incidents.
---
List critical incidents. Inspect evidence.
Ask before resolving an incident.'),
('incident-triage', 'references/policy.md',
 'text/markdown', '# Severity and escalation policy');
PROTOCOL

Virtual directory

  • skills/list and skills/get expose frontmatter and resource manifests.
  • resources/read serves skill://incident-triage/SKILL.md or its references.
  • Use SHA-256 and byte size over exact content; publish one unambiguous version via a view.
  • Claude: native skill discovery on supported plans. ChatGPT: tool fallback, concise server instructions or a separately packaged skill snapshot.
No files on the server

#200 uses rows and virtual resources. If ChatGPT needs a packaged skill, export it from ClickHouse at packaging time; that package is a reviewed snapshot, not the live database. A read_skill tool is a compatibility fallback, not native Skills activation.

Generic UI resource provider

11 / UI runtime

7. Let users and agents operate the same application.

Bundle the component once, store the bundle in ClickHouse, and run it in a host-managed sandbox.

TypeScript / illustrative SDK flow
// Component source (before bundling):
import { App } from "@modelcontextprotocol/ext-apps";

const app = new App({name: "Incident console",
                     version: "1.0.0"});

app.ontoolresult = (result) => {
  renderIncidentRows(result.structuredContent);
};

await app.connect();

// On an explicit refresh action:
const result = await app.callServerTool({
  name: "list_incidents",
  arguments: {severity: "critical"}
});
renderIncidentRows(result.structuredContent);
CONTRACT

The UI never becomes an auth bypass

  • Build with the MCP Apps SDK; inline or bundle scripts/styles into one approved HTML resource.
  • Render untrusted row values as text, not HTML. Do not put database credentials, bearer tokens or signing secrets in the iframe.
  • Use the host bridge for tool calls; do not connect the browser directly to ClickHouse.
  • App state is transient; durable selections, preferences and edits go through named tools.
Portability

Standard MCP Apps first. Keep useful model-readable output when UI is unavailable. Claude-specific app tools can let the model change current UI selection; OpenAI-specific entrypoints and window.openai helpers can enhance host integration, but should not be necessary for the core workflow.

8. Turn inserted data into agent-triggering events.

Build an append-only event/outbox projection; route it to subscribed clients via the connector.

Command insertopen_incident
→
Outbox tableeventId · payload
→
STREAM / pollsource checkpoint
→
Signed callbackChatGPT Work / dots
SQL
CREATE TABLE app.incident_outbox
(
    event_id UUID,
    event_time DateTime64(3),
    severity String,
    title String
)
ENGINE = MergeTree
ORDER BY (event_time, event_id)
SETTINGS enable_block_number_column = 1,
         enable_block_offset_column = 1;

-- Create an incremental materialized view
-- from open_incident to this outbox.
-- ClickHouse 26.6+ (experimental):
SET enable_streaming_queries = 1;
SELECT _block_number, _block_offset,
       event_id, event_time, severity, title
FROM app.incident_outbox STREAM;
EVENT CONTRACT

Persist the lifecycle in ClickHouse

  • Expose incident.opened with a severity filter and a bounded payload schema.
  • Persist subscriptions, leases, cursors, retry state and dedup keys; the generic dispatcher has no app-specific logic.
  • Use source identity plus stable event IDs; checkpoint only after durable enqueue.
  • Reauthorize long-lived consumers, verify callback signatures/challenges and enforce outbound URL policy.

ClickHouse streaming is experimental and limited to supported sources; use SQL polling for snapshot thresholds and older versions. ChatGPT uses a pre-final webhook profile. Verify its capability keys and webhook-id behavior separately. Claude Events support is unverified; use user-triggered refresh or other approved monitoring paths. Event receipt does not authorize writes.

13 / async work

9. Add long-running jobs and user decisions.

Tasks and Events solve different problems: a task is requested work; an event is something that happened.

P1 · TASKS

Durable job registry

  • Use a database-defined job catalog and job state/results in ClickHouse.
  • A generic worker leases authorized jobs, executes approved SQL and persists terminal status/result; implement cancellation, timeout and restart recovery.
  • Expose MCP Tasks when negotiated, with standard lifecycle operations and no session affinity.
  • Fallback: ordinary start_job, get_job, cancel_job tools; return a job ID immediately.
P1 · ELICITATION

Structured human input

  • A tool may need approval, missing parameters or a URL interaction.
  • Store pending request state in ClickHouse (or signed opaque request state), bind to principal, operation and expiry.
  • Use MCP Elicitation when negotiated. Otherwise expose prepare/confirm operations or a UI form with a validated confirmation token.
  • Never rely on model instructions or tool annotations alone to authorize consequential writes.
Host reality

Claude announced Tasks and Elicitation GA on Nov 24 for eligible individual plans, with organization rollout. OpenAI documents Elicitation; native MCP Tasks was not verified. Implement fallback job tools rather than block the portable experience.

15 / deployment

11. Deploy one endpoint, package for each host.

Do not mistake a custom connector that works for your team for a public plugin approved in both directories.

SHARED INFRASTRUCTURE

Production remote MCP

  • Stable HTTPS /mcp, Streamable HTTP, supported protocol negotiation.
  • External IdP: protected-resource and authorization discovery, PKCE S256, CIMD/DCR where supported; verify issuer, audience, expiry and scopes.
  • Map identity and roles safely to ClickHouse; test both hosts' actual OAuth clients. Use existing metrics, TLS, limits and logs.
  • Prefer a universal application endpoint with identity-based routing over arbitrary per-tenant URLs.
CHATGPT

Install / review

  • Add a custom MCP server as a plugin; scan and test in a supported surface.
  • For public distribution, submit the production endpoint with plugin metadata, privacy/support/terms URLs, domain verification and accurate tool annotations.
  • Packaged skills are optional; use a DB-exported snapshot if native MCP Skills is unavailable.
  • Keep tool/API versions stable and rerun review scans when metadata changes.
CLAUDE

Install / review

  • Add remote custom connector and test Chat / Cowork availability and authorization.
  • Use Claude's plugin/connector directory submission process; approvals do not transfer from OpenAI.
  • Verified listings and organization access affect entrypoints and embeds; file hosts need approval and supported listing URLs.
  • Confirm feature rollout on the intended account before promising the experience.

16 / design constraints

Stateless gateway ≠ system with no state.

Durable app state lives in ClickHouse. Some operational mechanisms cannot be wished away.

IDENTITY

Least privilege

  • Separate app roles from operator/DDL publisher roles.
  • Do not trust user-supplied tenant IDs; derive identity from validated credentials.
  • Scope direct resource URI reads, UI tool calls, skill manifests and event subscriptions to principal + cluster.
  • No authenticated fallback to shared DB credentials.
DURABILITY

Correctness boundaries

  • Append-only journal, projections, event IDs, durable checkpoints and recovery.
  • Coordinate worker leases and deduplication; ClickHouse sorting keys are not unique constraints or distributed locks.
  • For strict transactional state transitions, uniqueness, money or inventory, explicitly validate required guarantees or use a transactional dependency.
TRUST

Code and content

  • Treat COMMENT metadata, skill content and HTML as executable-influence surfaces; only trusted publishers may modify them.
  • Version/review HTML assets; restrict CSP and network access. Validate schemas, file sizes and callbacks.
  • Record audit IDs, status and counts without logging tokens, full secrets or sensitive content.
Where the thin-proxy principle stops

A generic worker or coordination/queue service may be necessary for reliable webhook retries, async jobs or outbound effects. It can keep domain decisions in SQL and store authoritative state in ClickHouse, but cannot promise atomic distributed leases, exactly-once delivery or safe transaction semantics just because the adapter is stateless.

18 / verification

Acceptance tests: prove an application, not a demo.

Ship a reproducible single-tenant fixture and test the same remote endpoint with both hosts.

PROTOCOL

Inspector + automated tests

  • Discovery, negotiated extensions, JSON schemas, resource MIME type and exact bytes, skill digests, structured results.
  • One write returns a generated ID; capped result does not stop the write.
  • Event subscription/refresh/unsubscribe; replay and retry; task cancellation; optional features reject or degrade predictably.
HOST

ChatGPT + Claude

  • Install/connect through real OAuth and exercise headless read and write.
  • Render and interact with the same UI; refresh, select and submit an authorized command.
  • Claude native skill loading; ChatGPT explicit fallback. ChatGPT Work event wake-up; verify no assumed Claude wake-up.
  • Test plans, admin policies, permissions and public review workflows separately.
PRODUCTION

Failure and tenant cases

  • Two principals, two clusters, two MCP replicas; no catalog or resource leak.
  • Credential expiry, wrong audience, denied role, revoked grant, malformed UI/skill metadata, SSRF and XSS probes.
  • Kill a consumer mid-delivery, restart, duplicate event, expired subscription; observe recovery.
  • Measure latency, output bytes, query/worker budgets and audit trails.
Verification scope

19 / conclusion

The application lives in ClickHouse.

Altinity MCP should be the reusable gateway for a whole class of database-defined applications.

Already on the roadmap

Views → reads
Tables → commands
RETURNING → receipts
Skills → expertise
Events → triggers

Next platform increment

UI resources + structured results
Typed app contracts + scoped resources
Tasks / Elicitation + file adapters when needed

Recommended decision

Implement portable MCP Apps over a ClickHouse resource table as the next major feature. Treat host-specific plugin surfaces as adapters around the same SQL-defined application, not as separate application backends.

The architecture is strongest for analytical and append-oriented workflows. It is not a general replacement for a transactional application server, an identity provider, or a durable job runner where the application's requirements demand those capabilities.
